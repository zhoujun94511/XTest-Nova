# 广告特殊场景关闭策略整改（2026-09-14）

## 目标

在覆盖优先探索中可靠退出全屏广告，同时避免把普通页面右上角菜单、收藏、分享等控件误判为广告关闭按钮。

## 判定与动作链

1. Activity 类名命中已知广告 SDK 组件时，视为强广告场景信号；广告 SDK 位于目标应用包内或独立进程包内均可识别。
2. 只有广告文案而没有关闭语义控件时，不启用角落盲点规则。
3. 强广告场景优先点击带 `close/dismiss/skip/关闭/跳过` 语义的控件。
4. 无语义控件时，仅在全屏视口顶部四分之一、左右角落四分之一内选择面积受限的可点击小控件，并排除 WebView 整体。
5. 倒计时期间不随机点击广告内容；关闭控件最多等待 35 秒出现。
6. 等待超时后执行 Back 回退，动作仍受既有特殊场景次数上限、会话所有权和新鲜度校验约束。

Activity 注册表只用于提高置信度，不作为点击任意区域的授权。注册表按 SDK 组件命名维护，不按广告素材文字或应用包名宽泛匹配。

## 后续维护

新增广告 SDK 时应先采集真实 `dumpsys activity` 组件名和 UI 层级，再更新注册表与样例；不要仅依据平台品牌名猜测组件。需要长期记录 `ad_detected`、等待耗时、关闭动作、Back 回退和恢复到目标应用的结果，以便识别 SDK 升级造成的规则漂移。
