# Nexus 到 Nova 迁移计划

## 基线

行为基线来自 `D:\\projectx\\XTest-Nexus`：

- 7912/8912 的 77 个历史“方法+路径”合同；
- 8912 Companion 接口；
- `app_process` shell Runner 调用链；
- Android 16 悬浮窗行为；
- ARM64 真机验证记录。

Nova 仓库内的自包含合同基线见[完整 77 项 HTTP 合同](../compliance/http-contract.md)，日常维护无需再跨项目查找路由含义。

Nova 不复制 Nexus 的 Smali、原始 DEX、恢复证据和历史二进制。

## 阶段

### M1：可维护骨架

- 完成 Agent、Runner、Companion 三层工程；
- 完成设备信息、前台包、唤醒、Monkey 生命周期；
- 建立单元测试、构建和部署脚本。

### M2：核心协议兼容

- 按 Nexus 合同补齐应用、文件、进程、性能和服务管理；
- 建立 77 个历史“方法+路径”合同自动比对，所有差异必须有明确原因；
- 增加 WebSocket 并发、超时和断线测试。

当前 M5.8C 已在 Android 13/16 完成独立夹具 Popup、录制回放、流服务及后台 Shell/PTY 终端回归。Nexus 历史合同达到 77/77；任意命令相关的 `/shell`、`/shell/background` 和 `/term` 默认拒绝，只能在回环部署中用显式兼容开关启用。运行以下命令可对照仓内已审查的 Nexus 路由基线：

```powershell
go run -mod=vendor ./agent/cmd/contract-check -reference .\docs\compliance\reference-http-contract.md -document .\docs\compliance\http-contract.md
```

## 验收原则

- 不以“能编译”代替真机行为验证；
- 不以固定成功响应代替功能；
- 不要求随机事件逐条一致，要求相同种子下策略可复现，并比较覆盖率、崩溃和关键状态；
- 所有不兼容变化使用版本化 API，不偷偷改变历史响应。
