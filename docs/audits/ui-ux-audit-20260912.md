# XTest Nova Web 控制台 UI/UX 审计与整改（2026-09-12）

## 审计结论

原控制台能够调用部分接口，但整体仍是研发验证页：设备原始字段和能力标签直接平铺、功能按接口而非用户任务组织、缺少跨流程目标上下文、运行状态反馈不连续，并遗漏智能探索及完整录制回放链路。移动端虽能折行，但导航、列表密度和操作优先级不足以支撑真实使用。

本轮在不引入第三方前端框架、打包器或远程资源的前提下，完成信息架构、视觉系统、交互状态、功能覆盖及代码结构重构。

## 主要问题与处理

| 审计维度 | 原问题 | 整改结果 |
|---|---|---|
| 信息架构 | 7 个接口型页签，文件、产物、诊断关系割裂 | 重组为概览、应用、自动化、性能、产物、诊断六个任务域 |
| 首屏层级 | 20 余项设备原始字段占据首屏 | 首屏仅保留设备、电量、内存、存储四项摘要，原始字段进入可展开详情 |
| 目标上下文 | 每个功能重复填写包名 | 增加全局目标应用，应用列表选择后同步到自动化、性能和产物筛选 |
| 自动化覆盖 | 仅提供 Monkey；录制回放只有查询状态 | 补齐智能探索预览/启动/状态/停止、录制启动/停止/用例库/回放及随机遍历完整链路 |
| 状态反馈 | 仅底部一行“处理中/完成” | 增加全局加载条、按钮级忙碌状态、Toast、会话横幅及各任务状态标签 |
| 诊断可读性 | 所有响应直接输出 JSON | 常用指标结构化展示，原始 JSON 收入可展开详情；组件、产物、用例均使用专用列表 |
| 产物可达性 | 产物仅显示原始 JSON | 按会话分组并为每个文件提供安全下载链接，保留包名、类型和数量筛选 |
| 响应式 | 小屏仅改单列，导航和内部列表仍拥挤 | 桌面侧栏、中等宽度图标栏、手机底部导航三级响应；390px 无横向溢出 |
| 无障碍 | 导航在紧凑模式缺少可靠名称，焦点反馈不足 | 增加语义标题、ARIA 标签、跳转链接、实时区域、键盘焦点与减少动画支持 |
| 维护结构 | HTML/CSS/JS 与终端资源全部平铺 | 拆为 `assets/css`、`assets/js`、`assets/media`；请求、渲染、交互三层 JS 独立 |
| 部署一致性 | 同版本覆盖部署可能复用旧静态缓存 | 静态资源改为重新验证并增加资源版本参数，避免新 HTML 与旧脚本混用 |

## 设计原则

1. 首屏回答“设备是否正常、能否开始测试、是否有任务正在运行”。
2. 目标应用只选择一次，后续功能共享同一上下文。
3. 默认展示可决策的信息，原始数据保留但不抢占视觉层级。
4. 开始操作为主按钮，查看为次按钮，停止操作使用独立危险色。
5. 不依赖 CDN、字体服务或前端框架，保证离线设备环境可用。

## 验证范围

- Chromium 实际页面桌面宽度视觉检查。
- 390 × 844 手机视口检查，页面 `scrollWidth` 与 `clientWidth` 一致，无横向溢出。
- 应用列表实际读取 64 个第三方应用，导航和目标选择可操作。
- 控制台无 JavaScript error/warning。
- 新资源路由及旧 `/static` 兼容资源均纳入 Go 回归测试。
- Android 13 与 Android 16 使用最新自包含 Agent 验证健康状态与资源响应。

最终双机验证中，每台设备的首页、7 个模块化资源和 2 个兼容资源均为 HTTP 200，健康状态均为 `ok`。浏览器控制台无 error/warning。
