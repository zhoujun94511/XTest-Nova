# Web 会话轮询审计与整改 Todo（2026-09-12）

## 审计结论

旧控制台每 10 秒并发读取运行时诊断和五类会话详情。即使设备完全空闲、页面只停留在运行概览，单个浏览器标签页仍产生 36 次请求/分钟。运行时诊断会读取 Go 内存统计，Runner 详情还会解析持续增长的事件日志；同一轮中同时读取两者会重复获取 Runner 状态。现有并发保护能够避免上一轮未完成时重入，页面后台也不执行请求，因此问题不是请求竞态，而是轮询粒度和频率不合理。

## 实施 Todo

- [x] P0：新增 `GET /v1/sessions/current`，只返回六类会话的轻量运行状态。
- [x] P0：Runner 新增锁内 `Activity()` 快照，轻量接口不读取和解析事件日志。
- [x] P0：运行时诊断复用轻量快照，避免诊断接口隐式触发 Runner 全量状态解析。
- [x] P0：固定 10 秒并发轮询改为单次完成后再调度，杜绝请求堆叠。
- [x] P0：空闲 30 秒、活动 3 秒、失败 10 秒重试；浏览器标签页进入后台后停止调度，回到前台立即刷新。
- [x] P1：概览等普通页面只轮询会话摘要；诊断页才读取运行时诊断。
- [x] P1：自动化页只读取当前或刚结束的 Runner、智能探索、录制、回放详情；性能页只读取性能详情。
- [x] P1：任务启动和停止成功后立即刷新摘要，不等待下一周期。

## 请求规模

| 场景 | 整改前 | 整改后 |
| --- | ---: | ---: |
| 普通页面、设备空闲 | 36 次/分钟 | 2 次/分钟 |
| 诊断页、设备空闲 | 36 次/分钟 | 4 次/分钟 |
| 普通页面、任务运行 | 36 次/分钟 | 20 次/分钟 |
| 对应任务页面、任务运行 | 36 次/分钟 | 约 40 次/分钟，仅包含摘要和相关任务详情 |
| 页面处于后台 | 0 次/分钟 | 0 次/分钟 |

空闲普通页面请求量下降约 94.4%。活动任务采用更高频率是为了保证开始、收尾和异常状态能够及时显示；任务结束后自动回落到空闲频率。

## 验证结果

- Go 全量测试、JavaScript 语法检查和 Go vet 通过。
- 发布门禁通过：目标合同 77、实现 77、覆盖 77、文档 77，缺失和文档偏差均为 0。
- Android 16（`83fc400c`）和 Android 13（`R5CN30EQKNM`）均完成短任务状态迁移验证，轻量接口真实观测到 `running`、`finalizing`、空闲三个阶段，最终无错误。
- 两台设备的摘要接口响应耗时分别为 4–14 ms 和 7–16 ms。
- 两台设备实际服务页面均加载 `assets/js/app.js?v=3`，脚本包含 `/v1/sessions/current` 且不包含旧固定轮询。

## 保留边界

`GET /v1/diagnostics/runtime` 继续保留原有字段和布尔型 `sessions` 结构，供诊断页和既有调用方使用。新增接口只承担控制台高频状态提示，不替代任务详情接口，也不改变 Stop 快速返回与后台产物收尾语义。
