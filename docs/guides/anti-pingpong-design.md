# 深度探索反 Ping-Pong 设计

## 问题定义

Ping-Pong 不只指单次 `A → B → A`。本项目按以下无进展循环统一处理：

- 自环：动作后仍为同一导航状态；
- 二环：`A → B → A` 重复；
- 多节点环：`A → B → C → A` 等周期重复；
- 间歇环：相同语义转移被其他无效动作打断后再次出现；
- 指纹漂移环：页面的节点索引、坐标或动态正文变化，但导航语义仍在相同状态间往返；
- 回退环：`BACK` 没有回到记录的父状态，随后被再次执行。

## 设计原则

成熟的模型探索器通常不会用单一页面哈希同时承担内容发现和环检测。Nova 采用三级身份：

1. **精确状态**：保留 Activity、树结构、节点和坐标差异，用于建立实际探索图；
2. **内容语义状态**：忽略坐标和动态数字，保留稳定控件/正文，用于跨物理指纹共享已尝试动作；
3. **导航循环状态**：以 Activity 和稳定动作集合构造粗粒度身份，用于识别内容加载无法掩盖的往返。

循环判定采用“有进展才重置”的滑动窗口：发现新的导航状态时清空怀疑窗口；同一窗口内连续周期或重复语义转移才会熔断。这样既能阻止多次 Ping-Pong，也不会把正常进入新页面、滚动发现新内容误判为循环。

## 在线策略

- 保存最近 64 条语义转移；
- 检测长度 1～8 的周期，连续重复 3 次时确认循环；
- 对被其他动作打断的重复转移，同一进展窗口内第 4 次确认循环；
- 确认周期后熔断周期中的全部相关边，而非只处理最后一条边；
- 熔断同时使用物理边和语义边，防止动态指纹生成新节点后绕过限制；
- 返回动作只允许出现在已知子状态，并验证实际目标是否为记录的父状态；
- 图耗尽是正常终态，不再自动进入无限随机输入；
- 只有层级采集失败才能进行随机降级，且连续预算最多 5 次；
- 同一动作的多个目标用次数统计选择稳定目标，不再由最后一次结果覆盖历史事实；
- 控件树采集前后双读 Activity；变化中的混合快照只等待，不入图、不执行。

## 可观测性

Go 探索状态新增：

- `cycleDetections`
- `blockedEdges`
- `unstableCaptures`
- `lastCycle`（周期、重复次数、关闭边和原因）

Runner 事件及图摘要新增：

- `cycle_detected`
- `edge_blocked`
- `fallback_action`
- `unstable_snapshot`
- `cycleDetections`
- `blockedEdges`
- `fallbackActions`
- `unstableSnapshots`

原始 `events.jsonl` 仍是判断是否存在环和是否误杀正常路径的主要证据。

## 资格门槛

1. 单元测试覆盖自环、二环、三环、动态物理指纹和被其他动作打断的重复转移；
2. Foloy 正常前向探索不能因一次返回或一次重复页面被误判；
3. 构造循环应在阈值内产生 `cycle_detected` 并熔断整个周期；
4. 熔断后动作数必须收敛，不能继续消耗全部时长或步数；
5. 图耗尽后 `fallbackActions` 必须保持为零；
6. Activity 在采集期间变化时不得生成混合场景。
