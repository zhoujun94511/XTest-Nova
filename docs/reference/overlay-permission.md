# 悬浮窗权限

Companion 需要系统特殊权限 `SYSTEM_ALERT_WINDOW`（显示在其他应用上层）。它不是运行时弹窗权限，`pm grant` 无效。安装 APK 也不会自动打开该开关。

## 启动流程

1. Agent 在 shell 身份下尝试 `appops set`（包模式与 UID 模式）。部分厂商会拒绝 shell 修改 AppOps，此时启动不会失败。
2. 能写成功则直接拉起悬浮窗。
3. 写不成功则打开系统「显示在其他应用上层」页。Android 11 起官方会忽略包名，进入应用列表；请选择 **XTest Nova** 并打开开关。应用名会复制到剪贴板，便于搜索。
4. 授权完成后 Agent 在后台检测权限并拉起悬浮窗，不必重新部署。HTTP 监听不会等待用户点完授权。
5. 标准设置页打不开时，回退到应用详情页。厂商安全中心的专用入口不预置在主路径，待对应系统出现静默授权失败后再补。

`server -d` 默认走上述流程。`--no-popup` 仍安装运行时，但不拉起悬浮窗。

## 已验证的系统族

下表只记录系统族与结果，不登记具体设备。结论来自本轮真机部署：卸载 Companion 后重新 `server -d`。

| 系统族 | 静默 AppOps | 首次启动 |
| --- | --- | --- |
| 原生 Android / Pixel | 允许 | 自动授权并显示悬浮窗 |
| 三星 One UI | 允许 | 自动授权并显示悬浮窗 |
| 荣耀 MagicOS | 允许 | 自动授权并显示悬浮窗 |
| vivo OriginOS | 允许 | 自动授权并显示悬浮窗 |
| 摩托罗拉 | 允许 | 自动授权并显示悬浮窗 |
| 小米 / POCO HyperOS | 允许 | 自动授权并显示悬浮窗 |
| OPPO / 一加 ColorOS（部分） | 拒绝 | 打开系统列表，用户打开开关后自动显示 |

静默授权被拒时，开发者选项里的「禁止权限监控」或「Disable system optimization」可能恢复 `appops set`，这是系统开关，应用不能代替用户打开。

## 与 LAN、无线调试的区别

悬浮窗权限只影响设备端控制条。`-AllowLAN` 开放 7912 的局域网 HTTP，不是悬浮窗授权，也不是系统无线调试。
